# Eager packages declare via mise's native `[tools]` table; lazy packages become real, portable shim files

> **Superseded in part by ADR-0007:** the eager half (the `[tools]` table, mise's native shim/activation, and `.mysh/mise/shims` on `PATH`) is dead — eager packages are now marked shim files prewarmed by one batched `mise install`. The lazy half (real, portable shim files in `.mysh/bin`) stands, and is now the mechanism for *every* package.

`.packages` was a bespoke declaration file mysh had to special-case out of `apply::render`/`diff::diff`, and both eager and lazy packages resolved onto `PATH` through one mysh-generated shim (unified in issue 13, which found mise's own shim/activation mechanism didn't work without a config file mysh never wrote). We're splitting that mechanism back apart: **lazy** packages become real files — a shim script checked into Source at the exact mirrored path (`profile/.mysh/bin/<name>` → `.mysh/bin/<name>`), rewritten to resolve `$HOME` and `mise` at run time instead of baking in a device-specific path, so the identical file is correct on every device and needs no special-casing to render. **Eager** packages move to mise's own native `[tools]` table in `config.toml` (already a tracked dotfile) — `add` writes entries via `mise config set "tools.<specifier>" <version> --file ...` (confirmed no install side effect), `apply`'s eager step becomes one blanket `mise install`, and `PATH` exposure rides mise's own shim/activation mechanism instead of a mysh-generated one. `.packages` disappears entirely; no new dependency is introduced, since every new piece of this (`config set`, `config get tools`, `install`) shells out to `mise`, already a dependency.

## Considered Options

- **Reuse issue 13's unified shim for eager too, just sourced from a `[tools]`-table declaration instead of `.packages`.** Rejected: once eager's declaration lives in mise's native format, generating a second, mysh-owned shim on top of it is pure redundancy — mise's own activation does the same job once the config file it depends on actually exists.
- **Rely on mise's native shim/activation without writing `[tools]` at all** (i.e. install with no config entry). This is what issue 13 tested and rejected as broken. Retested live against the current mise version: without a `[tools]` entry the native shim doesn't error the way issue 13 recorded — it silently falls back to whichever installed version is highest, which is worse (undocumented, non-deterministic across what else happens to be installed) rather than better. Only writing the `[tools]` entry made resolution deterministic.
- **Put lazy shim files in `.mysh/mise/shims` alongside eager's**, to cut down on `PATH` entries. Rejected after testing live: mise wipes and regenerates that entire directory from the `[tools]` table on every reshim (which `mise install` triggers automatically) — any unrelated file placed there, including a lazy shim, gets deleted on the next `apply` that has any eager package at all.

## Consequences

- `PATH` needs a second directory added going forward: `.mysh/mise/shims` (mise-owned, mise regenerates it wholesale — mysh must never write into it directly) alongside the existing `.mysh/bin` (mysh-owned: the `mysh`/`mise` binaries plus lazy shims).
- Eager and lazy packages no longer share a code path or a `PATH`-exposure mechanism — a deliberate reversal of issue 13's unification, now safe because eager gets its own config-file-backed mechanism instead of depending on the lazy path to work at all.
- `Teardown` needs no changes: it already deletes the isolated mise data dir wholesale (`teardown.rs:38-42`) rather than uninstalling packages individually: the per-package Application Log entries were always cosmetic, feeding only the pre-confirmation summary text.
- The real `profile/.packages` (~40 entries) needs a one-time migration: each lazy line becomes one real shim file, each eager line becomes one `mise config set` call.
