# Secrets use one shared passphrase, not per-device keypairs

Asymmetric encryption (age/SSH-keypair style) is the more common choice for "serious" secret management because it allows per-recipient revocation. We rejected it here because it has an unavoidable bootstrapping problem: the private key can never live in the repo, so it must reach every new or temporary device through a separate secure channel — directly conflicting with mysh's goal of working on as many devices as possible with minimal setup. mysh is also single-user, so per-device revocation isn't a requirement being sacrificed. Instead, every Secret is encrypted with a key derived (Argon2id) from a single shared Passphrase, typed on demand on any device. Cost: no per-device revocation, and a leaked Passphrase exposes every Secret in the repo.
