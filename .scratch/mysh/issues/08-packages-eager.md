# 08 — Packages: eager install via mise

**What to build:** Package declarations and eager installation. `mysh` declares CLI-tool packages (install specifier, optional binary-name override, eager/lazy classification), self-bootstraps `mise` if it's missing, and installs every eager package during `apply`.

**Blocked by:** 01 — Scaffold + plain-file Apply

**Status:** done

- [x] Packages are declared with a `mise`-compatible specifier — either bare (`go@latest`, for tools `mise` natively supports) or backend-prefixed (`github:`, `npm:`, `pip:`, `cargo:`, etc.) — plus an eager/lazy classification
- [x] The resulting binary name defaults to the bare specifier name and only needs to be declared explicitly when a backend-prefixed install produces a differently-named binary (e.g. `github:elio-fm/elio` → `elio`)
- [x] If `mise` is not already present on the device, `mysh` installs it automatically and records the bootstrap in the `Application Log`
- [x] Every package declared eager is installed via `mise install` during `apply`
- [x] Tests cover: `mise` absent → bootstrapped and logged; an eager package declared → installed and runnable after `apply` (using a stubbed `mise` on `PATH` to avoid real network installs)

## Comments

Implemented in new `src/package.rs` (declaration parsing/orchestration) and `src/mise.rs` (subprocess wrapper around the real `mise` binary). Packages are declared in a `.packages` file at the root of `Source` — tab-separated lines, `<specifier>\t<eager|lazy>[\t<bin_name>]` — treated as mysh metadata, not a dotfile: `apply::render` and `diff::diff` both exclude this exact top-level path from ordinary rendering/drift (a same-named file nested in a subdirectory is untouched, still an ordinary file). `default_bin_name` derives the binary name from the specifier (strip backend prefix, strip `@version`, take the last `/`-segment) when not explicitly overridden.

`mise::resolved_mise_bin` treats `mise` as usable either system-wide (already on `PATH`) or from an earlier mysh bootstrap; `ensure_installed` only runs the installer when neither holds, and only when at least one eager package is declared — a device with no packages (or lazy-only) never touches `mise` during `apply`. The installer (`curl -fsSL https://mise.run | sh`) is forced to install to a deterministic, mysh-owned path (`MISE_INSTALL_PATH=<target>/.mysh/bin/mise`) rather than trusting its own default (`~/.local/bin/mise`, not guaranteed to be on `PATH`) — the installer only ever writes that one binary, no `PATH`/rc edits, confirmed against the real installer's docs. `ensure_installed` resolves this once per `apply` and returns the binary to invoke, threaded through to every `mise::install` call rather than each one re-resolving it, so bootstrap state is checked exactly once regardless of how many eager packages are declared, and is never re-detected as "missing" on a later `apply`. The resolved path is recorded via `AppLog::record_mise_bootstrapped(path)` (`mise-bootstrapped\t<path>\n`, matching the log's existing `kind\tvalue` shape) so `teardown` (issue 11) can later delete exactly that file with no guessing. Each eager package is installed via `mise install <specifier>`, scoped to an isolated `MISE_DATA_DIR` under `<target>/.mysh/mise`, and its own successful install is recorded via `AppLog::record_package_installed`.

Tests: unit tests in `src/package.rs` (`default_bin_name` across bare/backend-prefixed/versioned specifiers, `parse_line` defaulting/overriding `bin_name` and rejecting an unknown classification) plus `tests/package_integration.rs` driving the real CLI — `mise`-absent bootstrap-and-log (via a fake `curl` on `PATH` that, like the real installer, writes a fake `mise` binary to `$MISE_INSTALL_PATH` instead of hitting the real network, and asserts the log records the exact mysh-owned path), a second `apply` against the same `target` reusing the already-bootstrapped `mise` without re-invoking the (deliberately removed) installer, no-op when no eager packages are declared (asserted by leaving `mise`/`curl` off `PATH` entirely), eager install-and-runnable via a stubbed system-wide `mise` (asserts the install call, the Application Log entry, and that the installed stub binary actually runs), the `.packages` file never rendered to `Target`, and a nested same-named file rendered normally. `cargo test` (52 tests) and `cargo clippy --all-targets` pass clean.

Reviewed via `/code-review` twice: first pass (Standards clean; Spec found two real gaps — installed packages weren't recorded in the Application Log, and the original `.packages` exclusion was scoped too broadly — both fixed) plus a follow-up idempotency fix (installer's unguaranteed default location, forced to a deterministic `MISE_INSTALL_PATH`). A second `/code-review` pass on that follow-up commit found two more real issues, both fixed: `mise --version` was being re-spawned once per eager package instead of once per `apply` (Standards axis — now resolved once in `ensure_installed` and threaded through); and the follow-up's own headline claim (a second `apply` skips the installer) had no test proving it (Spec axis — added `second_apply_reuses_bootstrapped_mise_without_reinvoking_installer`).
