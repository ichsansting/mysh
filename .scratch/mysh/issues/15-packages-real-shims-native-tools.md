# 15 — Packages: real lazy shims in Source, eager via mise's native `[tools]` table

**What to build:** Replace `.packages` (a bespoke declaration file special-cased out of `apply::render`/`diff::diff`) per ADR-0006 (`docs/adr/0006-eager-packages-native-mise-tools-lazy-packages-real-shims.md`):

- **Lazy** packages become real, portable shim files checked into Source at the mirrored path (`profile/.mysh/bin/<name>` → `.mysh/bin/<name>`), rendered by ordinary Apply. Shim content resolves `$HOME` and `mise` at run time, not at write time, so one file is correct on every device.
- **Eager** packages become entries in mise's own native `[tools]` table in `config.toml` (already a tracked dotfile). `add` writes entries via `mise config set`. `apply`'s eager step becomes one blanket `mise install`. `PATH` exposure for eager packages rides mise's own shim/activation mechanism (`.mysh/mise/shims`), not a mysh-generated shim — a deliberate reversal of issue 13's unification, safe now because eager no longer depends on the lazy shim path to work.

**Blocked by:** none (08, 09, 13 already shipped; this supersedes their mechanism, not their outcome)

**Status:** done

- [x] `.packages` file and its parser (`package::load`/`parse_line`/`Package`/`DECLARATIONS_FILE`) are gone
- [x] Lazy shim content is portable (no target-specific absolute paths) and idempotently identity-copied like any ordinary tracked file
- [x] `apply`'s eager step is one blanket `mise install`, not a per-specifier loop
- [x] `apply` still bootstraps `mise` for a lazy-only device (so the shim's bare `mise` call resolves later) and is still a no-op when nothing (lazy or eager) is declared
- [x] `add --lazy` writes a real shim file into Source; `add --eager` writes a `[tools]` entry via `mise config set`, never touching Target (requires an already-resolvable `mise` — system-wide or previously bootstrapped; errors clearly otherwise, since bootstrapping one would violate `add`'s "never touches Target" invariant)
- [x] `.mysh/mise/shims` added to `PATH` in `bootstrap.sh`, alongside `.mysh/bin`
- [x] Real `profile/.packages` (41 entries, not ~40) migrated: every lazy line → one real shim file, every eager line → one `[tools]` entry
- [x] `cargo test` and `cargo clippy --all-targets` pass clean

## Comments

Design reached via a `/grilling` session (see ADR-0006). Two live-tested findings that overturned assumptions from issue 13: (1) mise's native shim/activation mechanism, tested against the current mise version, does *not* hard-error without a `[tools]` entry the way issue 13 recorded — it silently falls back to the highest-installed version, which is worse (non-deterministic) rather than better; writing the `[tools]` entry makes it resolve deterministically, confirming the config-file approach issue 13 scoped out as "a larger change than what's needed" actually works. (2) Lazy shim files cannot live in `.mysh/mise/shims` alongside eager's — mise wipes and regenerates that whole directory on every reshim (verified live: an unrelated file placed there was deleted by the next `mise install`).

**Implementation notes:**

- `mise.rs` grew `config_path`, `install_declared` (blanket `mise install` scoped to `target`'s isolated data/config dirs), `declared_tools` (parses `mise config get tools --file` back into `name@version` strings, matching the Application Log's existing specifier format), `declare_tool` (`mise config set tools.<name> <version> --file`, creating the file first if absent), and `trust` — a live-discovered requirement: `mise` refuses to parse *any* config file outside its default lookup locations, including via an explicit `--file`, unless trusted first (found while migrating the real `profile/.config/mise/config.toml`, which has a templated `[env.UV_PYTHON]` entry). `mysh` trusts unconditionally — it's always a path `mysh` itself renders from `Source`, content the user already authored and asked `mysh` to manage, no different in trust level from every other file `mysh` already renders/sources unsandboxed. `resolved_mise_bin` (the read-only "don't bootstrap, just check" resolver) is now `pub(crate)` so `add`'s eager path can reuse it without violating "`add` never touches `Target`".
- `package.rs` lost `.packages` parsing entirely; `apply` gates on two cheap, `mise`-free presence checks (`is_lazy_declared`: any file in `source/.mysh/bin`; `is_eager_declared`: a `[tools]` substring in `source`'s `config.toml` — not a real TOML parse, just a gate for whether it's worth invoking `mise` at all) so a package-free device still never touches `mise`, matching the pre-existing invariant.
- Found and fixed a real bug while writing the first lazy-package integration test: `apply::walk_files` unconditionally skipped any directory literally named `.mysh`, at *any* depth — correct when `.mysh` only ever existed as Target's generated runtime state, wrong now that `Source` has its own legitimate `.mysh/bin/`. Split into `walk_files` (still skips `.mysh` — for walking `Target`, where it's still always generated state) and a new `walk_source_files` (only skips `.git`) — `apply::render` and `diff::diff`'s own Source-side path collection now use the latter; `add`'s folder-add and `diff`'s directory-mode-tracking scan of `Target` still use the former.
- `apply::copy_if_changed` now preserves the source file's executable bit (previously no ordinary tracked file needed this — secrets had their own restrictive-permission writer, nothing else was ever meant to be executable). Needed for a lazy shim, now an ordinary tracked file, to stay runnable after being identity-copied into `Target`.
- Migrated the real `profile/.packages` (41 entries, not ~40 — miscounted earlier) by dogfooding the new `add` CLI itself: one invocation per lazy/eager line, run against `profile/` as `Source` and the real `$HOME` as `Target` (safe — `add` never touches `Target`, confirmed by the implementation itself). Five specifiers (`rust@stable`, `python@3.13`, `node@latest`, `bun@latest`, `uv@latest`) needed a second/third bin name for the same specifier (`cargo`/`rustc`/`rustup`, etc.) — `add`'s specifier-level duplicate check (preserved from the original CLI, which had the same limitation) blocks a second `add` for an already-declared specifier regardless of `--bin`, so those extra files were hand-written directly, the same workaround the original `.packages` file itself must have used to get there.
- Test coverage: unit tests in `package.rs` (portable shim content, `default_bin_name`, the two presence-check gates) and `mise.rs`; `tests/package_integration.rs` rewritten around an extended fake-`mise` shell stub that round-trips a tiny `[tools]` section through `config set`/`config get`/blanket `install` well enough to exercise the real code paths (mise bootstrap for lazy-only and eager devices, blanket-install + Application Log recording, lazy shim identity-copy + exec-bit preservation, eager landing in `.mysh/mise/shims` vs. lazy in `.mysh/bin` — asserted as staying in their own distinct, non-overlapping directories — and the full install-on-first-invocation lazy shim exec path with `HOME` explicitly pointed at `target`, since the shim now resolves it at run time); `tests/add_integration.rs` rewritten for the new `add --lazy`/`add --eager` mechanics, including the "no resolvable `mise`" error path and the `--bin`-with-`--eager` rejection; `tests/teardown_integration.rs`'s package fixture rewritten to write real files directly instead of a `.packages` line, with an added assertion that the eager package's mise-owned shim is removed on teardown same as everything else. `cargo test` (90 tests: 20 lib + 70 across 13 integration binaries) and `cargo clippy --all-targets` pass clean (same pre-existing per-binary `dead_code` warnings on now-unused-in-that-binary `tests/support.rs` helpers as before this change, nothing new in kind).
